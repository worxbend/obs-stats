# obs-stats — working notes

A btop-style terminal dashboard for OBS Studio. Single Rust binary, no daemon.

## Layout

```
src/
  obs/        obs-websocket 5.x: protocol, auth, session task, typed payloads
  metrics/    Snapshot (the model), History (ring buffers), derived rates
  config/     YAML schema, XDG paths, loading, secret resolution
  tui/        app (state machine), keys (keymap), views/, widgets/, run (terminal)
  probe.rs    one-shot collection, shared by `once` and the screenshot generator
  cli.rs      clap definitions and flag→config layering
examples/
  screenshot.rs   renders real frames to docs/images/*.svg
```

The layers only depend downward: `obs` → `metrics` → `tui`. Keep it that way.

## Invariants worth preserving

**The UI performs no I/O.** `tui::app::App::handle` is a pure state transition
returning an optional `Command` for the session task. Only `tui::run` touches
the terminal. This is what makes the whole interaction model testable without a
TTY, and it is why the render loop can never block on OBS.

**The session task owns the socket.** It reconnects with backoff, polls on a
timer, and pushes `Update`s. The UI never awaits a round trip. A hung OBS must
degrade to a visibly stale dashboard, never a frozen terminal.

**Passwords never become strings that can be printed.** They live in
`error::Redacted`, whose `Debug` and `Display` both render `<redacted>`. The
config file has no password field at all — only the *name* of an environment
variable.

**Decoders are total.** Everything in `obs::stats` falls back to a default
rather than failing the poll. OBS adds fields between point releases and drops
others when an output is inactive; a dashboard that blanks out because one
number moved is worse than one showing a zero.

**Counters are per-stream where it matters.** `GetStats` reports totals since
OBS launched. `Snapshot` captures a baseline when a stream starts so the UI can
report "this stream". Don't regress this — it is the main thing the OBS stats
dock gets wrong.

**Glyphs in aligned columns must be single-width.** Emoji are double-width and
silently shift every column after them on that row. `View::icon` and the audio
row's mute marker are both covered by tests that assert this.

## Testing

`cargo test` — 350+ tests, no terminal and no live OBS required. The TUI is
exercised through ratatui's `TestBackend`; the client through synthetic
`Update`s. Rendering tests cover every view × every theme, plus cramped
terminals, so a layout that underflows is caught.

Before committing:

```sh
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test
cargo run --example screenshot -- --demo   # must produce no git diff
```

CI fails if the screenshots drift from the code.

## Screenshots

`docs/images/*.svg` are generated by `examples/screenshot.rs`, which draws real
frames and serialises the cell buffer to SVG. Generation is deterministic — a
fixed frame counter and a triangle-wave pseudo-noise function, no RNG and no
wall-clock in the output.

Regenerate with `--demo` (synthetic data). Without the flag it uses a live OBS
if one answers, which is useful for eyeballing but not for committing.

`--text` dumps the layouts as plain text, which is the fastest way to check a
layout change.

## Things that are deliberate

- **Read-only.** Selecting a scene does not switch it. This is a monitor.
- **No daemon.** The reference project (`obsctl-rs`) is daemon-first because it
  writes; a read-only dashboard does not need one.
- **Cursor clamps, never wraps.** Jumping from the newest log line to the oldest
  on one keypress is disorienting.
- **Pause freezes metrics but not connection state.** A paused dashboard must
  never hide the fact that OBS went away.
- **Chart y-axes window in.** A 5.4–6.5 Mbps series on a 0–7 Mbps axis is a flat
  line. See `History::axis_range`.
